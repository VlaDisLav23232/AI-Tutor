# AI-Tutor · Бланк

AI tutor that helps 11th-graders prepare efficiently for the NMT. The MVP covers the **Ukrainian language** test (30 tasks, 45 test points):

- **Diagnostic (15 min, 16 tasks)**: your starting score for each topic.
- **Topic scores on the NMT 100–200 scale**, shown as gauges with three levels: below 140, 140–169, and 170+. All topics count equally, and the overall score is the average of the topics you've tried.
- **Practice**: an endless stream of tasks, in two modes:
  - «Усі теми» mixes 15% mistakes and «!» tasks, 20% topics due for review, 35% weak topics and 30% any topic.
  - «Найслабші теми» uses only your 5 weakest topics. The pool is recalculated before every task, so a topic that improves out of the bottom 5 is replaced by the next weakest.
  - The «Слабка тема» label appears only for topics currently in your bottom 5; ordinary tasks have no label.
  - After each answer, the topic's score animates up or down.
  - The session summary shows how much each topic moved.
- **Topic tests**: 10 tasks per topic, chosen from a compact grid of topics with filters.
- **Saved tasks**: ★ marks a favourite; ! means "give me this exact task again".
- **NMT variant**: 30 tasks in the real exam's topic layout, with a timer and a 100–200 result.
- **Daily goal and streak**: 10 tasks a day keeps the streak going. The dashboard shows a week calendar, your best streak, and a "correct in a row" combo during practice.
- **AI only on request**: explanations («Пояснити (AI)»), "explain differently", questions about the task, and "one more task like this".

## How it works

- **Tasks.** 399 real NMT 2026 tasks come from `materials/nmt_2026_tasks_by_category.json`. Only the task fields are used; the explanations in that file are ignored.
- **Exam layout.** How often each topic appears at each exam position is computed from the tasks and used to build realistic NMT variants.
- **Explanations (agent).** «Пояснити (AI)» runs an explanation agent ([`src/lib/ai/explain.ts`](src/lib/ai/explain.ts)). The model never sees the key. At each step it picks one action:
  - `search_rules`: search the Правопис with its own query (free, local).
  - `check_answer`: the code says "correct" or "wrong" against the key (free).
  - `submit`: the code checks the answer and that every option is explained. It either rejects the submission with a reason or accepts it, which ends the run.

  An accepted submission is marked `verified`. After 2 wrong answers or 5 steps, the explanation is written with the key and marked `needs_review`, and the student is told AI wasn't sure. The usual case is one call (submit right away). The student sees each step live, and results are cached in the DB.
- **Explanation format (v2).** No textbook rule up front. Each explanation is a short verdict on every option plus a one-sentence takeaway. The screen shows:
  1. the student's option, if it was wrong;
  2. the correct option;
  3. the remaining options;
  4. «Як запам'ятати».

  The style depends on the topic (`profileOf` in `explain.ts`):
  - **Stress:** no rules, only mnemonics; the code checks every capitalised stress against the official list.
  - **Phraseology:** only «1 — Г, бо …» lines, no etymology.
  - **Spelling, grammar, usage, syntax, sentence order:** each has its own instructions.

  Mnemonics come from [`src/data/kb-mnemonics.json`](src/data/kb-mnemonics.json) (not yet reviewed by a teacher). A stress task whose words all appear in the official list is explained by code, with no AI call. Explanations in the old v1 format are treated as missing and regenerated the next time a student asks.
- **Rule grounding.** RAG over the Правопис 2019 (`materials/sdm-ukrayinskii-pravopis-vidannia.pdf` → `src/data/rules.json`) supplies the rules.
- **Generated tasks:**
  - Stress and foreign-word tasks are built deterministically from the knowledge base (`materials/Наголоси.md`, real tasks), with no LLM.
  - Phraseology and other single-choice tasks are generated by Sonnet and kept only if Claude Haiku, solving blind, reaches the same key.

## Run locally

```bash
npm install                         # also generates the Prisma client
cp .env.example .env                # fill in the values (see comments)
npx prisma dev --name nmt --detach  # local Postgres; put the printed URL in DATABASE_URL
npm run db:push
npm run db:seed                     # categories + 393 tasks
npm run dev                         # http://localhost:3000
```

- **Without Google credentials:** set `AUTH_DEV_LOGIN=true` to get a demo login button.
- **AI provider:** `AI_PROVIDER=anthropic` (default, needs `ANTHROPIC_API_KEY`) `AI_PROVIDER=gemini` (needs `GEMINI_API_KEY`) or `AI_PROVIDER=groq` (needs `GROQ_API_KEY`, free tier). Only the chosen provider is used; if it fails, the AI feature shows an error. Model ids can be overridden, see `.env.example`.
- **Without the provider's API key:** everything works except AI explanations, chat and LLM generation.

**AI costs.** Every AI call is logged with its cost in the server console and recorded in the `AiUsage` table. When the total reaches `AI_BUDGET_USD` (default $1.50), AI features switch off with a message. Rough prices with Claude (Gemini Flash is several times cheaper):

| Call | Cost |
| --- | --- |
| Explanation (Sonnet, cached per task after the first time) | $0.02–0.03 |
| Chat answer (Sonnet) | ~$0.01 |
| Generated phraseology or other task, including the Haiku check | ~$0.01 |

Explanations are never generated automatically: after answering, the student presses «Пояснити (AI)», and the result is saved and reused for free. You can precompute some, but all 393 would cost roughly $8–12:

```bash
npm run ai:explain -- --limit 20    # explain 20 tasks (~$0.50); without --limit it only prints an estimate
npm run ai:eval                     # agreement with the key per topic (add `-- --generate 2` to test generation; costs money)
```

## Other commands

| Command | What it does |
| --- | --- |
| `npm test` | Unit tests (scoring, parsing, pickers, generators) |
| `npm run build:kb` | Rebuild the stress / idiom / foreign-word knowledge base |
| `npm run build:rules` | Rebuild the Правопис § index |

## Deploy (Vercel + Neon)

1. Create a Neon database and use its pooled connection string as `DATABASE_URL`.
2. Run `npm run db:push && npm run db:seed` against it.
3. Set the env vars from `.env.example` in Vercel, without `AUTH_DEV_LOGIN`.
4. Add `https://<domain>/api/auth/callback/google` as a redirect URI in Google Cloud.

## Before a public launch

- The 100–200 conversion in `src/lib/scoring.ts` is a linear approximation. Replace it with the official УЦОЯО 2026 table.
- Check the official exam time and set it in `EXAM_MINUTES`.
- The task base is reconstructed from a commercial collection. Switch to official УЦОЯО demo and past tests.

`materials/` holds all source materials: tasks, Правопис, НМТ programme, stress and idiom lists, and the CustDev context.
